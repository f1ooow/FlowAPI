# 内置分组可用性监控

## Goal

为已登录用户提供一个独立的“分组监控”页面，通过 New API 内置的定时合成请求持续检测指定分组的真实可用性，不依赖 Uptime Kuma 或其他外部服务。

## Background

- 用户只关心分组级可用性，不需要在普通页面展示分组内部模型或渠道明细。
- 每个分组由管理员指定一个检测模型；检测按可配置的全局频率运行。
- 页面形态参考已有分组状态卡：当前状态、窗口可用率、延迟、历史色块和最后检测时间。
- 页面只对已登录用户开放；内部渠道、错误详情和检测模型只对管理员开放。
- CCH 状态页和 EF-new-api 分组监控主要聚合真实业务流量；本功能必须在无业务流量时仍能产生连续状态数据。

## Requirements

- 管理员可以启用/停用分组监控、选择被监控分组、从该分组当前可用的模型中指定检测模型，并为每个分组指定与原生渠道测试一致的请求格式和流式开关。
- 定时任务必须经过项目现有 system task 租约机制，避免多实例重复探测。
- 探测使用分组和模型参与正常渠道选择，并发送最小化上游请求。
- 探测沿用正常 Relay 请求并写入“模型测试”消费/错误日志，便于在请求日志中追溯；但不得扣减用户或令牌额度、累计用户/渠道用量、改变渠道启停状态或写入现有 `perf_metrics`。
- 每次探测记录分组、成功状态、总延迟、命中渠道、错误分类和检测时间；公开给普通用户的接口必须脱敏。
- 普通用户页面仅展示分组级摘要和历史，不显示检测模型、渠道 ID、渠道名称或原始错误。
- 管理员可查看检测配置、最后一次内部结果，并手动触发一次检测。
- 状态定义：最近一次成功为可用，最近一次失败为不可用，缺少结果或结果超过两个检测周期为无数据。
- 可用率按选定窗口内 `成功探测数 / 已完成探测数` 计算；页面默认展示最近 24 小时。
- 历史色块按时间桶内最后一次完成的探测结果着色；时间桶内的成功数/总数仍用于可用率统计，不能因为同桶较早的失败而覆盖较新的成功状态。
- 结果持久化必须兼容 SQLite、MySQL 5.7.8+ 和 PostgreSQL 9.6+。
- 所有新增可见文本必须支持项目现有前端 i18n。

## Out Of Scope

- 匿名公开状态页。
- 模型级状态卡、渠道级状态卡和外部状态页 API。
- 告警通知、事件认领、维护窗口和 SLA 报表。
- 依赖或嵌入 Uptime Kuma。
- 使用探测结果自动禁用或启用渠道。

## Acceptance Criteria

- [ ] 管理员保存至少一个有效“分组 + 检测模型 + 请求格式”配置后，系统按频率创建且仅创建一次跨实例探测任务。
- [ ] Claude、Gemini、Responses、Embedding、Rerank 和图像检测复用 New API 原生渠道测试的请求体、路径与 RelayFormat；旧配置自动按模型选择合适的协议。
- [ ] 配置页只提供所选分组当前可路由的模型，后端拒绝不存在的组合；历史配置中仅大小写不一致的模型名会归一化为渠道登记的准确名称。
- [ ] 一次成功或失败探测均会形成可查询的持久化结果，并正确更新 24 小时可用率和最后状态。
- [ ] 无真实用户请求时，分组历史仍随定时探测持续产生。
- [ ] 探测前后用户/令牌额度、用户/渠道用量、渠道状态和 `perf_metrics` 均不变化；成功和失败均能在请求日志中按“模型测试”与请求 ID追溯。
- [ ] 已登录用户可以通过独立导航入口进入分组监控页面；未登录访问会进入现有登录流程。
- [ ] 系统设置中的分组监控入口直接展示完整配置，不再经过二级按钮或弹窗。
- [ ] 普通用户 API 和页面不暴露检测模型、渠道或原始错误；管理员可以查看这些诊断字段。
- [ ] 全量“立即检测”提交后，全部受测卡片立即显示测试中并保持到 system task 结束；重复提交幂等返回现有任务，不向用户暴露 409。
- [ ] 单分组检测只锁定并更新目标卡片，不阻塞其他分组的检测按钮；失败提示只展示一次后端可读错误。
- [ ] 页面覆盖加载、空数据、错误、过期、可用和不可用状态，并在桌面与移动端无溢出或重叠。
- [ ] 后端核心聚合和调度行为有确定性测试，前端关键状态与交互有行为测试。
- [ ] Go 测试、前端类型检查、涉及文件 lint 和生产构建通过。

## Technical Notes

- 现有 `controller/channel-test.go` 直接测试固定渠道；分组探测复用正常 Relay 的分组选择与重试，并沿用“模型测试”日志标识。
- 现有 `controller/system_task_handlers.go` 和 `service/system_task.go` 提供定时任务、租约、进度与完成状态。
- 现有 `pkg/perf_metrics` 只统计真实 relay 指标；synthetic probe 使用独立表，避免污染模型广场。
