# 渠道成本倍率与用户最终倍率

## Goal

将渠道行内“获取上游倍率”操作替换为本站可控的渠道成本倍率，并让管理员可以按计费分组决定是否把渠道倍率计入用户账单。全局模型价格同步是独立能力，继续用于从官方预设、公开价格库或上游获取模型定价。用户选择分组时只看到与自己所属用户分组对应的最终倍率或最终倍率区间，不需要理解内部的分组倍率、用户倍率和渠道倍率。

## Background

- 渠道此前存在行内“获取上游倍率”操作，但全局 `/api/ratio_sync/*` 是模型价格同步管理功能，二者不能等同。
- 现有 `GroupGroupRatio`/“特殊倍率规则”表示“用户分组使用某个计费分组时的最终覆盖倍率”，不是独立乘数。
- 用户确认：所谓“用户倍率”本质上由用户所属分组决定，例如普通用户和 VIP 用户；它是“用户分组 x 目标计费分组”的倍率矩阵，不是单个用户的字段。
- 当前用户分组选择接口只返回一个倍率值，前端 API Key 分组选择器也只支持显示单值。
- 当前计费支持普通模型倍率、固定价格、阶梯表达式、按次任务和异步任务；渠道可能因自动分组、亲和选渠或重试而变化。

## Terminology

- **用户分组**：用户账户所属分组，例如 `default`、`vip`。
- **计费分组**：用户/API Key 请求使用的渠道分组，例如 `default`、`premium`。
- **分组倍率**：计费分组自身配置的基础倍率。
- **用户倍率**：某个用户分组使用某个计费分组时的独立乘数；未配置时为 `1`。
- **渠道倍率**：每个渠道的成本倍率；默认值为 `1`。
- **最终倍率**：本次实际用于计费的分组倍率、用户倍率和可选渠道倍率的乘积。

## Requirements

### R1. 删除渠道行内获取倍率，保留全局模型价格同步

- 删除渠道列表或渠道编辑器中的行内“获取上游倍率”操作，以显式渠道成本倍率取代该渠道级工作流。
- 保留模型定价页的“上游价格同步”、`/api/ratio_sync/channels`、`/api/ratio_sync/fetch`、控制器、DTO、测试和 OpenAPI 条目；该能力同步的是全局模型价格、模型倍率和计费表达式，不是渠道成本倍率。
- 保留 `/api/ratio_config` 对外公开本站模型倍率的能力。
- 保留渠道上游模型列表检测和同步能力；模型列表同步不属于倍率同步。

### R2. 渠道成本倍率

- 每个渠道可配置一个渠道成本倍率，业务默认值为 `1`。
- 存量渠道升级后不改变当前账单；未显式配置的渠道按 `1` 处理。
- 渠道倍率必须是有限正数，并受到防止异常计费和溢出的合理上限约束。
- 渠道倍率的变更必须写入管理审计，但不得暴露到匿名或普通用户接口。

### R3. 分组是否计入渠道倍率

- 每个计费分组增加“计入渠道倍率”开关，存量分组默认关闭。
- 开关关闭时，渠道倍率因子固定为 `1`。
- 开关开启时，渠道倍率因子取本次最终成功渠道的渠道倍率。
- 管理界面把该开关放入现有分组定价表，不新增与用户任务无关的独立页面或重复状态展示。

### R4. 用户倍率语义

- 现有“特殊倍率规则”改名并改义为“用户分组倍率”。
- 用户倍率由“用户分组 x 计费分组”定位，未配置时为 `1`。
- 用户倍率不再覆盖分组倍率，而是参与最终倍率乘法。
- 管理界面应以可读句式表达规则，例如“VIP 用户使用 premium 分组时，用户倍率为 0.75x”。

### R5. 唯一计费公式

所有计费模式统一使用：

```text
最终倍率 = 分组倍率 x 用户倍率 x 渠道倍率因子

渠道倍率因子 =
  实际成功渠道倍率    分组勾选“计入渠道倍率”时
  1                  分组未勾选时
```

- 普通模型倍率、固定价格、阶梯表达式、按次任务和异步任务都必须遵守同一公式。
- 自动分组、渠道亲和、指定渠道和跨渠道重试都以本次最终成功渠道为准。
- 若重试后的最终倍率高于预扣依据，必须在发送该次上游请求前补足预扣；若更低，统一结算退回差额。
- 计费日志为管理员保留各个因子和最终倍率，普通用户界面不拆分展示这些内部因子。

### R6. 用户选择分组时的最终倍率展示

- 未勾选“计入渠道倍率”的分组只返回和显示最终单值：`分组倍率 x 用户倍率`。
- 已勾选的分组返回和显示最终区间：

```text
区间下限 = 分组倍率 x 用户倍率 x 分组内当前最小渠道倍率
区间上限 = 分组倍率 x 用户倍率 x 分组内当前最大渠道倍率
```

- 区间统计范围是属于该计费分组且当前启用的全部渠道，不按具体模型进一步过滤。
- 最小值等于最大值时显示单值，不显示重复区间。
- 没有启用渠道时显示不可用状态，不伪造 `1x`。
- `auto` 继续显示“自动”，不展示误导性的聚合区间。
- 用户只看到最终单值或最终区间，不显示“分组倍率”“用户倍率”“渠道倍率”拆分。
- 区间仅通过已认证的用户自助接口返回；匿名分组接口不得返回可反推渠道成本的数据。
- 区间是当前分组全部启用渠道的总体提示，不构成某个具体模型的固定倍率承诺；实际账单仍以最终成功渠道为准。

### R7. 历史配置兼容迁移

- 旧“特殊倍率”按以下公式迁移为新用户倍率：

```text
新用户倍率 = 旧特殊倍率 / 目标计费分组倍率
```

- 目标分组不存在时按旧运行时回退语义使用分组倍率 `1` 计算。
- 目标分组倍率大于 `0` 时，迁移后在未启用渠道倍率的情况下，最终倍率必须与升级前一致。
- 目标分组倍率为 `0` 且旧特殊倍率也为 `0` 时，新用户倍率迁移为 `1`，最终仍由零分组倍率保持免费。
- 目标分组倍率为 `0` 且旧特殊倍率大于 `0` 时无法用纯乘法等价表达。迁移必须检测并列出冲突，不能静默改变账单；冲突解决前继续保留旧语义并阻止标记迁移完成。
- 迁移具有持久化版本标记且必须幂等，应用重启不得重复除法。

### R8. 用户侧计费隐私

- 管理员日志可以在 `other.admin_info.billing_ratios` 中查看完整倍率拆分。
- 普通用户使用日志只保留已经合成的最终倍率/最终费用；必须删除历史日志中可能存在的顶层 `user_group_ratio`、`base_group_ratio`、`channel_ratio`、`include_channel_ratio`、`effective_ratio` 和 `billing_ratios`。
- 匿名分组接口不得返回分组基础倍率。
- `/api/pricing` 只能返回已经合成的用户可见最终倍率值；不得返回可与最终区间相除从而恢复渠道倍率的分组基础倍率或用户倍率。
- 普通用户响应中不得出现 `cost_ratio`、`channel_ratio`、`base_group_ratio`、`user_group_ratio` 或 `billing_ratios`。用户可以看到最终单值或区间，但不需要知道区间由渠道成本组成。

## Constraints

- SQLite、MySQL >= 5.7.8、PostgreSQL >= 9.6 必须同时支持。
- 新数据库字段不要依赖可能造成跨数据库反复迁移的 GORM 业务默认标签；默认值由 getter/规范化逻辑保证。
- 所有额度转换继续使用 `common/quota_math.go` 的安全转换函数，并保留饱和审计。
- 异步任务必须使用提交时的倍率快照，管理员之后修改配置不得重算历史任务价格。
- 前端新增或修改的用户可见文本必须覆盖全部支持语言。
- 当前工作区存在大量并行未提交改动，实施和提交必须使用明确文件白名单，不得使用 `git add .` 或 `git add -A`。

## Out Of Scope

- 不改变模型倍率、固定模型价格或阶梯表达式本身的配置语义。
- 不按模型计算不同的分组倍率区间。
- 不为单个用户增加独立倍率字段。
- 不删除 `/api/ratio_config`、`ExposeRatioEnabled` 或渠道上游模型列表检测。
- 不改变渠道路由权重、优先级、亲和策略和自动分组顺序。
- 不把渠道成本倍率公开给匿名用户或在普通用户界面中单独展示。

## Acceptance Criteria

- [ ] AC1：渠道列表和渠道编辑器不再提供行内获取倍率操作；新版模型定价仍可访问“上游价格同步”，`/api/ratio_sync/*`、`/api/ratio_config` 和上游模型列表检测均正常工作。
- [ ] AC2：新增和编辑渠道可保存合法渠道倍率；未配置的存量渠道读取为 `1`；非法、非有限、非正数或超过上限的值被拒绝。
- [ ] AC3：分组定价表可以保存“计入渠道倍率”开关，存量分组默认关闭。
- [ ] AC4：用户倍率按“用户分组 x 计费分组”读取，缺省为 `1`，且不再覆盖分组倍率。
- [ ] AC5：在分组倍率 `2`、用户倍率 `0.8`、渠道倍率 `1.5` 且开关开启时，所有适用计费模式的最终倍率均为 `2.4`；开关关闭时均为 `1.6`。
- [ ] AC6：首选渠道失败并重试到不同倍率渠道时，预扣、最终结算、用户/渠道已用额度和消费日志都以最终成功渠道为准，不发生少扣、重复扣费或错误退款。
- [ ] AC7：异步任务保存渠道倍率和最终倍率快照，配置变更或任务轮询节点变化不影响该任务的后续差额结算和退款。
- [ ] AC8：普通用户分组选择器对未启用渠道倍率的分组显示最终单值；对已启用的分组显示最终最小值到最大值；值相同时显示单值，无启用渠道时显示不可用，`auto` 显示自动。
- [ ] AC9：用户分组选择器和列表中不单独出现分组倍率、用户倍率或渠道倍率；匿名接口不返回最终区间或任何可反推渠道成本的字段。
- [ ] AC10：普通历史特殊倍率配置迁移前后最终倍率相等；迁移重复执行不改变结果；零分组倍率冲突被显式阻断和报告。
- [ ] AC11：消费日志的管理员信息能够审计分组倍率、用户倍率、实际渠道倍率、是否计入渠道倍率和最终倍率；非管理员日志继续隐藏管理信息。
- [ ] AC12：SQLite 真实迁移和回归通过；MySQL/PostgreSQL 至少通过跨方言迁移/SQL 兼容检查，若没有 live 实例必须明确标注未验证范围。
- [ ] AC13：管理员日志保留完整倍率拆分；普通用户日志、匿名分组接口和 `/api/pricing` 均不暴露或可直接反推出渠道成本倍率，用户侧只看到最终倍率/最终区间。
