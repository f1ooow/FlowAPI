# 渠道今日消耗统计

## Goal

在管理员「渠道」列表中增加「今日消耗」一列，让管理员无需进入日志页就能对比各渠道当天的计费用量。

实现阶段只修改本地代码与本地测试；生产部署在用户授权后单独执行。

## Background

- `channels.used_quota` 是渠道累计用量，没有日切快照，不能反推今日数值。
- 消费日志已包含 `channel_id`、`quota`、`created_at` 和日志类型，可以在不新增表或迁移的前提下聚合。
- `LOG_DB` 可能与主库分离，也可能是 ClickHouse，因此不能把渠道查询与日志聚合写成跨库 JOIN。
- 标签模式会在前端将多个渠道聚合成一行，今日消耗需要同步求和。

## Requirements

### R1 统计口径

- 「今日」按中国标准时间（UTC+8）自然日计算：当天 `00:00:00` 至当前时刻。
- 渠道时区不依赖服务器或浏览器的本地时区。
- 只累计 `LogTypeConsume` 正向消费日志；退款不冲减今日消耗。该口径与现有首页「今日用量」保持一致，并避免跨日退款产生负数。
- 消耗值使用现有 quota 单位，前端沿用「已使用 / 剩余」的货币 / Tokens 格式化规则。

### R2 后端数据链路

- 渠道列表与渠道搜索的每个返回项都提供可空的 `today_used_quota`。
- 在取得当前页渠道后，对这些渠道执行一次按 `channel_id` 分组的日志查询；禁止逐行查询。
- 查询必须兼容 SQLite、MySQL、PostgreSQL 和独立 ClickHouse 日志库。
- 成功查询但渠道今日无消耗时返回 `0`；消费日志已关闭或聚合查询失败时返回 `null`，避免把「不可用」误报成零消耗。
- 新增统计是补充信息；其失败不应让渠道管理列表整体不可用。
- 不新增数据表、索引或定时任务。

### R3 前端展示

- 桌面表格在「已使用 / 剩余」之后增加「今日消耗」列。
- 移动端渠道卡片同步展示今日消耗。
- 标签聚合行展示其子渠道的今日消耗之和；只要有一个子渠道值不可用，聚合值也显示不可用。
- 财务数值遵循现有敏感信息显示开关：隐藏时显示遮罩，不泄露精确数值。
- `0` 显示为有效的零值，`null` 显示为 `--`。
- 本轮不支持按今日消耗排序，避免主库分页与独立日志库排序产生不一致。
- 用户可见文案通过 i18n 提供。

## Acceptance Criteria

- [x] 普通列表和搜索结果都在同一 API 响应中返回当前页各渠道的 `today_used_quota`。
- [x] 同一渠道当天多条消耗被求和，其他渠道、前一天和非计费日志不进入结果。
- [x] 后端每个列表请求最多增加一次分组聚合，不会随渠道行数产生 N+1 查询。
- [x] 北京时间日界经确定性测试覆盖，不受运行机器时区影响。
- [x] 日志不可用时，渠道列表仍能打开且今日消耗显示 `--`。
- [x] 桌面表格、移动卡片和标签聚合行都显示正确的今日消耗，并遵循敏感数据遮罩。
- [x] 受影响的 Go 测试、前端测试、TypeScript 检查、定向 lint 和前端构建通过。
- [x] 本地实现与验证完成，并在用户授权后部署至 HK；未查询生产业务数据。

## Out of Scope

- 按今日消耗排序或筛选。
- 新增每日汇总表、累计快照或历史补数。
- 修改现有 `used_quota` 累计口径或首页「今日用量」。
- 未经授权的生产变更、生产业务数据查询或超出本次发布范围的生产验收。
