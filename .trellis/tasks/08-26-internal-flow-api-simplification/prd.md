# Internal Flow API simplification

## Goal

将当前 new-api 实例收敛为面向内部团队使用的单一前端：减少消费级营销、充值引导和聊天入口，只保留 API 网关的核心管理与使用路径；管理员可将指定用户设为无限账户额度，同时继续准确统计该用户的实际用量。

本任务已获得用户明确批准并进入实施阶段；当前 RC 作为 Flow API 实验环境持续部署验收。

## Product Principles

- 内部团队优先：页面服务于创建密钥、配置渠道、查看模型、查看日志和管理用户，不以充值转化或营销展示为目标。
- 单一产品形态：不提供主题、布局、语言和经典/新版 UI 选择器。
- 统计与扣费分离：无限额度仅免除账户余额不足和账户扣减，真实用量、请求日志、`used_quota` 等统计仍必须记录。
- 协议兼容优先：删除“聊天/游乐场”产品功能，不删除标准 OpenAI 兼容的 `/v1/chat/completions` API 能力。
- 保守处理历史数据：删除签到功能时不自动删除已有数据库表或历史记录。

## Current-State Findings

- 当前代码已经移除了 Classic 前端：`theme.frontend` 只接受 `default`，旧值也会迁移为 `default`。因此本任务不再删除第二套前端，只需移除主题配置入口并固定新版 UI。
- 主题抽屉、语言切换器、使用引导、推荐操作、聊天菜单、Playground 路由、签到 API/设置/UI 都仍有独立代码入口。
- API Token 已支持 `unlimited_quota`，但用户账户本身只有 `quota` 与 `used_quota`，尚不支持“无限账户额度”。
- 用户已于 2026-08-26 移除仓库中对 new-api 与 QuantumNous 标识的临时保护规则，当前任务可以执行面向内部实例的 Flow API 前端 rebrand。

## Requirements

### R1. Freeze the selected UI configuration

- 删除主题设置按钮、主题配置抽屉以及用户可见的主题/布局偏好设置。
- 最终 UI 固定为截图中当前选中的配置：
  - 颜色模式：仅浅色；不提供手动浅色/深色或跟随系统切换。
  - 颜色预设：默认。
  - 字体：Auto。
  - 圆角：Auto。
  - 密度：默认。
  - 侧边栏：侧边栏布局。
  - 页面布局：默认。
  - 内容宽度：居中。
  - 方向：从左到右。
- 不能只隐藏入口；旧 Cookie 或本地偏好也不能继续让不同用户看到其他主题或布局。
- 保留响应式布局，但产品界面始终使用浅色语义色，不再响应系统深色模式。

### R2. Remove dashboard onboarding and recommendations

- 从概览页删除“开始使用”引导区及其创建密钥、添加额度、发送请求步骤。
- 删除右侧“推荐操作/保持平台就绪”区域。
- 删除后重新组织概览页剩余内容，避免大面积空洞；不新增解释性卡片或营销文案。

### R3. Simplified Chinese only

- 删除所有语言切换入口和语言偏好设置。
- 前端始终使用简体中文，不读取浏览器语言或历史语言偏好。
- 技术实现可以保留现有 `t()` 调用作为低成本的上游合并边界，但运行时只能加载/选择简体中文资源。
- 本要求不改变外部 API 协议、模型名、代码示例和必须保持原文的技术标识。

### R4. Rewrite the public homepage as a one-screen gateway entry

- 保留公开的 `/` 首页，但完全重写当前默认营销内容，桌面端和移动端都应在一个首屏内完成主要信息与操作。
- 页面只承担两个任务：用一句简洁文案说明 Flow API 是 API 网关，并引导用户登录或进入控制台。
- 默认营销首页不渲染顶部导航栏；首屏主体直接承担品牌说明与主要操作。
- Hero 最多包含产品名称、一个两行以内的标题、一段简短说明和全页唯一的主要按钮；不添加功能列表、模型列表、支持协议列表或第二层宣传文案。
- 删除默认首页的 Stats、Features、HowItWorks、CTA、支持客户端、模型数量、营销指标、终端演示和长 Footer。
- 默认使用项目原有 Logo 几何并将展示名称改为 Flow API；不再继续使用本轮试制的自绘标志。
- 页面仅使用浅色模式和现有语义色、字体系统，不创建与控制台割裂的第二套视觉系统。
- 保留现有管理员自定义 `HomePageContent` 的覆盖能力；仅在未配置自定义内容时渲染新的 Flow API 默认首页。
- 首页不内嵌登录表单。未登录时 Hero 唯一主要按钮显示“登录”并进入现有 `/sign-in`；已登录时同一位置显示“进入控制台”并进入 `/dashboard`。

### R5. Remove check-in

- 删除用户签到入口、签到日历/状态、签到 API、签到系统设置及相关前端类型和请求封装。
- 新部署不再依赖签到数据模型，运行时不再读写签到记录。
- 不自动执行破坏性数据库迁移来删除已有 `checkins` 表；历史表可保持休眠，后续由管理员明确决定是否清理。

### R6. Remove chat and Playground product surfaces

- 删除侧边栏“聊天”分组及所有外部聊天客户端入口。
- 删除 Playground 页面、前端路由、相关设置和专用 `/pg/...` 后端入口。
- 删除 dashboard/onboarding 中对 Playground 的引用。
- 保留网关的标准聊天补全协议和渠道转发能力，包括 `/v1/chat/completions`；本要求不是删除模型的 Chat Completions 能力。

### R7. Add administrator-controlled unlimited user quota

- 用户账户新增持久化的“无限额度”状态，默认为关闭。
- 只有现有管理员授权链路可以开启或关闭该状态。
- 管理员编辑用户时可直接切换无限额度，不使用特殊超大数字模拟无限。
- 无限用户发起正常 API 请求时：
  - 不因账户余额为零或不足而拒绝。
  - 不扣减账户钱包余额，也不依赖充值或订阅余额。
  - 仍执行正常请求验证、渠道选择、模型权限、分组倍率、API Token 权限及速率限制。
  - 仍记录实际模型用量、请求日志、费用估算、`used_quota` 和请求次数。
- API Token 的额度限制与用户账户无限状态保持独立：账户无限不自动把每个有限 Token 改为无限；管理员仍可使用现有 Token 无限额度功能。
- 用户列表和编辑界面明确显示“无限额度”以及累计已用额度，不能把已用量隐藏为零。
- 管理员在额度弹窗确认后，当前编辑抽屉必须立即切换到“无限额度”状态，隐藏有限额度输入框和 `$0`，并保留可再次进入额度设置关闭无限额度的操作。
- 用户缓存模式必须包含该字段并处理缓存 schema 升级，不能出现数据库已开启但缓存仍按有限额度拒绝的情况。
- 预扣、结算、退款和异常失败路径都必须保持一致，不能产生负扣费、重复退款或伪造统计。

### R8. Keep one frontend implementation

- 保持现有 `default` 前端为唯一前端。
- 保留旧 `theme.frontend` 值归一化到 `default` 的兼容行为，避免旧数据库配置导致启动或页面异常。
- 删除任何仍会让管理员误以为可以切换 Classic UI 的可见配置入口（如存在）。

### R9. Flow API frontend rebrand

- 将用户可见的前端产品名称从 New API/new-api 改为 Flow API，包括默认系统名称、顶栏、登录/注册页、首页、页面标题、favicon、默认 Logo、系统设置预览和其他前端品牌位。
- 默认沿用项目原有 Logo 资产和几何，只将产品展示名称改为 Flow API；后续收到用户正式 Logo 后再单独替换。
- Logo 必须验证浅色、小尺寸 favicon 和移动端顶栏效果，不能裁切、模糊或产生视觉错位。
- 系统设置仍可允许管理员上传部署实例自己的 Logo；未配置自定义品牌时必须回退到 Flow API，而不是 New API。
- 本任务只做产品展示层 rebrand，不主动重命名 Go module、import path、后端 package、数据库表、Docker 镜像或其他会显著增加上游合并成本的技术标识，除非它们会直接暴露在用户界面中。
- 开源发布前恢复 new-api 上游归属属于独立的发布门禁；本任务记录该要求，但不在当前内部 RC 版本中提前恢复。

### R10. Remove subscriptions

- 删除用户钱包、管理员侧栏、用户操作菜单和系统设置中的订阅计划、购买与管理入口。
- 删除 `/subscriptions` 前端路由及订阅 feature 代码；旧地址不能再进入订阅页面。
- 后端不再注册 `/api/subscription/...` 与仅服务于订阅商品管理的 API，也不启动订阅额度重置任务。
- 新请求的资金来源只能是无限额度或钱包余额，不能继续选择已有订阅作为扣费来源。
- 不自动删除现有订阅表、订单或历史记录；历史数据保持休眠，避免升级部署造成破坏性数据丢失。

### R11. Keep email and password as the only account authentication surface

- 登录与注册只保留用户名/邮箱和密码流程；删除 OAuth、Passkey 和二步验证的登录入口及可用后端路由。
- 删除系统设置中的 OAuth 集成、自定义 OAuth 和 Passkey 配置页面，不再允许管理员重新开启这些方式。
- 个人资料只保留邮箱绑定和修改密码；删除第三方账号绑定、Passkey、二步验证、登录会话、访问令牌、通知方式和偏好设置。
- 管理员用户操作中删除第三方绑定、Passkey 重置和二步验证重置；不再暴露非邮箱绑定管理能力。
- 邮箱绑定使用独立的用户邮箱路由，不再挂在 OAuth 路径下。
- 对历史上已经开启二步验证的账号，密码校验成功后直接进入正常密码登录，避免移除 2FA 页面后账号无法登录。
- 不自动删除 OAuth、Passkey、2FA 或登录会话相关历史表和数据；这些数据保持休眠，避免破坏性迁移。

### R12. Preserve global model price synchronization

- 保留新版模型定价中的“上游价格同步”页签，以及从官方预设、公开价格库或上游 `/api/pricing` 获取模型价格、模型倍率和计费表达式的能力。
- 保留该全局管理能力使用的 `/api/ratio_sync/channels`、`/api/ratio_sync/fetch`、控制器、DTO 和前端组件。
- “模型价格同步”与渠道的“成本倍率”是两个独立概念：前者维护全局模型定价，后者影响指定渠道参与用户计费时的成本因子。
- 不恢复渠道列表或渠道编辑器中的行内“获取上游倍率”操作；渠道成本倍率继续由管理员显式配置。

## Acceptance Criteria

- [ ] 顶栏、个人设置和系统设置中不再出现主题、配色、字体、圆角、密度、侧栏、内容宽度、方向或语言切换控件。
- [ ] 清除浏览器站点数据后的桌面端和移动端均使用固定的目标 UI；带有旧主题 Cookie 的已有浏览器也被归一化到同一效果。
- [ ] 概览页不显示使用引导或推荐操作，剩余核心信息在常用桌面视口内布局完整且无异常空白。
- [ ] 所有可见产品界面固定为简体中文；浏览器语言和旧语言偏好不能切换界面语言。
- [ ] `/` 保留为公开页面，但默认内容在常用桌面和移动视口的一个首屏内完成品牌说明与登录/进入控制台操作。
- [ ] 首页不展示模型、协议、客户端、功能清单、统计数字、排行榜、定价或支持能力等营销内容。
- [ ] 首页只使用一个主要 CTA；未登录用户点击“登录”进入现有 `/sign-in`，登录用户点击“进入控制台”进入 `/dashboard`，首页本身不复制认证表单。
- [ ] 管理员已有的自定义 `HomePageContent` 仍可覆盖默认首页，空配置时才显示新的 Flow API 单屏首页。
- [ ] 用户和管理员界面均无签到入口；签到 API 返回不存在，且升级部署不会破坏已有数据库。
- [ ] 用户和管理员界面均无聊天/Playground 产品入口；对应前端路由和专用后端入口不可访问。
- [ ] 标准 `/v1/chat/completions` 网关请求仍可正常转发。
- [ ] 管理员可把普通用户切换为无限额度，再切回有限额度。
- [ ] 开启无限额度后，当前用户编辑抽屉立即显示“无限额度”及说明，不再显示 `0.000000`、`$0` 或有限额度调整输入。
- [ ] 无限用户在余额为零时可请求；有限用户保持现有余额校验行为。
- [ ] 无限用户的请求日志、实际用量和累计已用额度正常增长，账户余额不被扣成负数。
- [ ] 有限 API Token 对无限账户用户仍执行 Token 自身的额度限制；无限 Token 继续按现有语义工作。
- [ ] SQLite、MySQL 和 PostgreSQL 的用户字段迁移兼容，Redis/内存用户缓存均能正确传播无限状态。
- [ ] 未配置自定义系统品牌时，用户可见界面统一展示 Flow API 名称、项目原有 Logo、favicon 和页面标题。
- [ ] Logo 在浅色桌面端、移动端及 favicon 尺寸下均清晰可辨，没有裁切、模糊或布局跳动。
- [ ] 默认营销首页没有顶部导航栏，首屏主体没有因导航占位产生额外留白。
- [ ] 前端不再出现订阅入口或订阅路由；后端订阅 API 返回不存在，订阅重置任务不再启动，历史订阅表和数据不被删除。
- [ ] 登录、注册、个人资料和系统设置均不再出现 OAuth、Passkey 或 2FA；相关后端入口返回不存在。
- [ ] 个人资料不再出现“设置与偏好”、通知方式、登录会话或访问令牌，只保留邮箱绑定和密码修改。
- [ ] 邮箱绑定仍可用且不再依赖 `/api/oauth/...` 路径；历史上启用 2FA 的账号仍可使用密码登录。
- [ ] 新版模型定价页显示“上游价格同步”页签，可从官方预设、公开价格库或所选上游获取并选择性应用模型定价；渠道列表不出现行内获取倍率操作。
- [ ] 后端 module/import path 等非用户可见技术标识保持稳定，避免无收益的大范围重命名。
- [ ] 通过相关 Go 测试、前端测试、`bun run build`、Go 构建和真实浏览器桌面/移动端验证；不以付费上游模型调用作为本任务的必需验收。

## Out of Scope

- 删除或重写标准模型 Relay 协议、渠道适配器和计费表达式体系。
- 自动删除历史签到表或其他生产数据库数据。
- 自动删除历史订阅表、订单或其他订阅数据。
- 自动删除历史 OAuth、Passkey、2FA、认证流程或登录会话表及数据。
- 删除或以渠道成本倍率替代全局模型价格同步能力。
- 使用大整数、负余额或跳过日志的方式模拟无限额度。
- 重命名 Go module、import path、数据库表、后端 package 或 Docker 镜像等非用户可见技术标识。
- 为未来开源发布恢复上游归属；该工作作为发布前独立门禁处理。

## Notes

- 用户最新明确意图优先于早期截图或工作草稿；本 PRD 已完成需求收敛，不再保留阻塞实施规划的开放问题。
