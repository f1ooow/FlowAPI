# FlowAPI 渠道与模型覆盖补齐

## 目标与价值

将广州 KeliAPI 已配置的媒体供应商直接接入 FlowAPI，统一供 Keli Canvas、Keli Agent 及其他产品使用。补齐适配器、模型映射、计费和可运维配置；KeliAPI 的代码、配置和现有流量保持原状。Wan 只接入 Rolldek 渠道，FastAI 渠道仅接入其 Seedance 模型。

执行主体是 Codex；不按人工人天估算。2026-09-22 用户批准本地实现与验证；2026-09-25 用户明确说“可以上线现在”，已授权 HK FlowAPI 发布并导入既定渠道、基准价格及 `image` / `vedio` 分组。代码已实现，本轮发布前根模块测试、relaykit 独立构建和前端 typecheck 通过；生产部署与真实供应商验收尚未记录，不把本地检查写成线上可用性证明。

## 证据基线

2026-09-22 只读核对：KeliAPI 为 20 个渠道 / 92 个唯一模型 ID；FlowAPI 为 37 个渠道（34 启用）/ 53 个唯一模型 ID。差集共 51 个 ID：48 个源媒体 ID 对应 14 条源媒体渠道，另有 3 个历史文本别名；按当前目标范围，FastAI 的两个 Wan ID 排除，目标配置覆盖 46 个媒体 ID，Wan 仅保留 Rolldek 的两个模型。完整范围见 [模型清单](research/model-inventory.md) 与 [逐模型矩阵](research/coverage-matrix.json)。配置存在不等于端点可用。

代码与协议证据、FastAI 类型 60 的缺口、源价格异常、两边币种配置相同等事实统一记录于 [基线](research/coverage-baseline.md)；不把旧评估中的推断当作迁移依据。

## 完成定义

- **计划交付**：父子 PRD、design、implement、依赖、上下文清单、逐模型范围及验收门槛齐全，通过文档与任务结构检查。
- **代码交付**：R1–R5 的接口和计费契约、必要迁移、管理界面、确定性测试及构建已完成；配置草案可审阅。自动化测试通过不代表供应商实测完成。
- **FlowAPI 完备（最终）**：R0 中全部媒体能力有真实端到端证据并按批准的价格/分组启用；模型列表、提交、轮询、结果读取、账单闭环通过。因凭据或外部供应商阻塞的条目单独列出，不能将总体任务标为完成。

## 范围边界与决定

- FlowAPI 直接维护供应商；不经 KeliAPI 再转发，不导入 Keli 中反向指向 FlowAPI 的 69–73 号渠道，防止循环依赖。Wan 只配置 Rolldek 75，FastAI 64 不配置 Wan 别名。
- 选择性移植协议能力，保留 FlowAPI 当前倍率快照、溢出保护、接口和数据库兼容性；不整体合并 fork。
- 分为 video、media、images、pricing 四个可独立验收的子任务，父任务负责共享协议及最终集成。
- 不切换 Canvas/Agent 网关地址，不下线 KeliAPI，不处理无关文本模型升级或旧任务清理。
- 现有图片价格任务 `09-13-image-resolution-pricing` 的 GPT/Gemini 规则只做必要回归，不重做其定价。

## 决策与外部输入

用户已确定采用 Keli 源零售配置作为部署基准，图片归 `image`、视频音频归 `vedio`，并于 2026-09-25 授权当前发布。基准价格不代表已验证供应商成本，独立的未来售卖价字段仍可留空。Viapi 按实际媒体类型拆为两条目标渠道，因此 14 个源渠道产生 15 个目标渠道；总计仍为 46 个公开模型。FastAI 的两个按秒路由与同名公开 token 价格冲突，保留为禁用证据，四个 Seedance 公开模型均仍有原生路由。发布和逐项实测结果由父任务记录，未验证条目不标为可用。详见 `release-config-review.md`。
